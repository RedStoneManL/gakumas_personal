# HIF 专属回忆能力：目录与接入审计

核查日期：2026-09-10。范围：当前本地主数据与 golden 桥接代码。

**效果数据已取得 105 条，覆盖 105 张目标卡；自动 golden 转换通过 105/105。**

这类能力来自 HIF 本战结束后生成的回忆，仅在 HIF 生效。同效果不可重复叠加；本地官方帮助页明确此限制。

它是“使用指定种类的卡之后触发”的能力，并非只绑定到回忆携带的某一个卡副本。目标搜索不限制强化等级。

| 效果模板 | 条目数 | 每场考试次数 |
|---|---:|---:|
| 再动 +1 | 26 | 2 |
| 再动 +1，抽 1 张 | 45 | 1 |
| 随机移除山札/弃牌中的 1 张眠气 | 34 | 1 |

移除眠气的搜索范围是山札与弃牌，目标进入除外区，不包括手牌。再动指技能卡使用次数 +1，不等于把原卡效果再发动一次。

## 当前接入结论

- 所有 105 条 ability → skill → 培育触发 → 外层附加效果 → 卡使用后触发 → 实际效果引用均已解析，目标卡的普通版与强化版也均能映射到 golden ID。
- 培育 loadout 已读取 HIF 限定与重复不叠加，并能挂载主数据附加效果。
- GoldenProduceBridge.enchant 自动解析第一回合计时器、内层卡使用后触发、原生目标卡 ID、效果顺序和场内次数。调用者无需手写 DSL override。
- 本次审计已将 105 条声明交给原生 golden 实际初始化；下一回合没有重复挂载。三类行为的实跑回归见 tests/test_hif_memory_golden.py。
- 每条效果是考试级监听器：指定卡的普通版、强化版、多个副本以及后续生成的副本共享次数，不使用某张卡的局部绑定。每场新考试重置次数；中场 snapshot/restore 保留已消费次数和随机状态。
- 按外层 enchant 的稳定 ID 去重，保留首个声明顺序；同 ID 不同效果报错。跨轮累积的 StartAudition 授予不会导致重复挂载，其他不同来源的普通累积效果不会被此去重器合并。
- 首回合 turn 阶段挂载监听器；卡本体效果执行后触发回忆，再执行之后由卡挂载的 afterCardUsed 效果。移除找不到合法目标时仍消耗本次回忆触发次数。
- 不支持或发生语义变更的主数据字段会报错，避免静默仅执行一部分效果。HIF 场景限制由培育 loadout 解析层执行。

## RL 配置入口

全局培育：从目录中取 ability_id，放入 ProduceMemorySpec.ability_ids，再作为 build_idol_loadout(..., memories=(memory,)) 的记忆编成。进入 HIF 考试时会通过 StartAudition 自动转换，无需逐张卡添加绑定。

单场自定义考试：可以直接把同一转换结果作为 make_training_entry 的 memory_abilities；它不依赖具体卡副本编号。示例：

```python
from gakumas_arena import TrainingExam, make_training_entry
from gakumas_arena.produce import GoldenProduceBridge
from gakumas_rl.repository.master_data import MasterDataRepository
from gakumas_rl.simulation.produce.items import RuntimeExamStatusEnchantSpec

bridge = GoldenProduceBridge(MasterDataRepository())
ability = bridge.enchant(RuntimeExamStatusEnchantSpec(
    "enchant-p_ef-hif_memory-p_card-01-act-1_001-enc02"), 0)
exam = TrainingExam(make_training_entry(
    [30, 31], turn_types=["vocal"], memory_abilities=[ability]))
```

调用 TrainingExam.restore(snapshot) 恢复一场考试，不要重新创建 entry 充当中场恢复；新建 TrainingExam(entry) 表示一场新考试，会重置回忆次数。
