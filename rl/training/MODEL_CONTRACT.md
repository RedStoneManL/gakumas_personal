# 第一版网络与状态合同

这份说明描述 `gakumas_training` 当前实现，完整机制设计要求仍见 `design/rl-state-schema-20260910`。它不是全部引擎效果执行正确性的证明。

## 输入与语义

每次真实选择提供一个 `DecisionContext`：任务、决策种类、公开观察，以及有序的合法候选。全培育观察同时包含培育资源、日程和课程规则、当前结算帧、机制定义闭包，以及需要时的考试状态。单场任务不附加培育状态。只有一个合法选择时由适配器直接执行，不制造策略训练样本。

编码器将观察编译成 `EncodedDecision`：节点特征、带角色与顺序的关系边、程序树边、深度和候选节点索引。特征词表是显式追加的符号表，和模型一起保存；不对整张卡的名字或整段 JSON 做哈希编码。卡副本身份用于连接候选与实际卡牌，卡、饮料和道具定义使用各自的引用命名空间。

数值保留字段绑定，输入同时提供固定比例的原始数值与带符号的对数辅助特征。缺失、零、null、布尔值和整数键各自区分。这些是输入编码；终局奖励仍只做固定正比例缩放。

原生考试效果使用 Arena 公开的有效 AST。培育效果保留真实参数和定义引用，并补入已登记的操作家族与语义标签。未知原生算子、未登记的效果类型/参数或容量溢出会报错，不截断成一个不完整状态继续训练。当前所有 2,114 条培育效果及 2,070 条考试效果都通过了字段与语义标签准入检查，执行结果等价仍需按可达路径验证。

## buff 压缩

原生考试的限时 buff 已有引擎分桶，编码保留 `amount/turns/fresh` 等实际字段。培育侧另有只读聚合投影和贡献账本：已认证的固定整数属性加成按触发、谓词、目标、期限及结算条件分桶；同质来源的加减替换更新贡献。不同触发 phase 的监听者不会无故阻止合并，同一事件中可能改变结算的监听者仍保留边界。

第一版自动认证集中在普通“获得任意卡片／获得饮料 → 固定 Vo/Da/Vi 加成”、确定触发且无独立次数上限的支援规则。独立概率、次数、来源约束及更复杂程序保留实例。通用账本也区分永久和临时期限、加法/乘法/最大值操作；这不代表所有此类引擎效果都已自动取得聚合资格。

聚合后的来源效果不再完整重复展开到模型。Arena 仍执行游戏结算，投影不替代引擎逐条触发，也不预先模拟整条连锁。账本和静态缓存不能让同一公开状态的输出依赖观察历史。

## 网络

1. 将每个字段/符号和绑定的数值联合编码成节点特征。
2. 按程序树深度由叶到根归纳，使深层条件、代价与效果数值能够到达所属卡牌或规则节点。
3. 进行可配置层数的关系消息传递，让候选、卡实例、定义、资源和上下文交互。
4. 每个候选查询当前图的节点，输出一个动作 logit；单独的价值分支预测同一个整局终局目标。

策略和价值分支共享前面的语义计算。默认宽度 64、关系层数 2、符号向量维度 16、词表容量 65,536，单个观察上限 32,768 个节点；这些是可配置的第一版起点，不表示最优规模或已测出所有培育状态的峰值。批处理只拼接实际节点，候选补齐部分严格屏蔽，不按最大节点上限填满每条样本。

两个任务分别实例化这套组件，拥有独立的参数和词表。考试中的全培育决策使用全培育模型自身，不调用单场冲分模型。

## 训练与扩展

PPO 重用采样时已经编译的 CPU 图数据，并用当前参数重新前向。静态定义缓存不含会过期的神经网络输出。行为分布是合法候选上的 Categorical；多选通过有序的条件子选择和合法 STOP 表达，每个真实子选择保存自己的行为概率，失败事务不提交这些记录。

增加新机制时，需要补足 Arena 的公开规则表达、语义准入及相应验证；只有名称新增而结构已受支持的内容可复用现有机制编码。新增算子、改变字段含义或超过容量需要显式升级合同和模型/词表，当前不支持把不兼容 checkpoint 当作精确恢复。
