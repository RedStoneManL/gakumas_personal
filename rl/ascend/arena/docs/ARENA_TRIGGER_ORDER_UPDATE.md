# 触发顺序：先用确定性默认

2026-09-08。按用户最新取舍，道具触发的精确先后暂缓校准，不阻塞HIF基础建设，不要求穷举排列或专门追加采样。规则已更新为 `arena-content-rules/4`。

## 当前默认与替换位置

同一阶段的P道具／状态附魔监听者使用 `stable_id_lexicographic/1`：

1. 按附魔定义 `enchant_id` 的字典序。
2. 同ID按 `source_identity` 字典序，缺省为空字符串。
3. 两者相同则按实例 `uid` 数值升序。

字符串区分大小写，使用Unicode字典序；不以卡名翻译、UI位置、输入列表或道具／状态类别决定优先级。同ID的不同道具实例仍各自消费次数；原有同一道具在同批内的去重继续有效。

例如同阶段有 `demo/a_focus`（集中+3）、`demo/b_score`（基础分8），即使注册时先放后者，也先获得集中再得11分。这是明确标记的合成默认示例，不是真实游戏顺序的证据。

实现集中在 [resolution.py](../gakumas_rl/simulation/exam/resolution.py) 的 `TRIGGER_ORDER_POLICY` 与 `trigger_order_key`。模拟日志 `trigger_batch.detail.trigger_order_policy` 记录政策，`decisions` 记录本批实例顺序。后续有足够证据时修改这一公共排序入口，并升级规则版本；无需逐张卡改写效果。

排序范围只限同阶段的附魔监听者。卡文有序效果、既有阶段边界、自动用卡FIFO队列、成长监听者的既有区域／牌序均保留。同批资格仍在任何效果执行前冻结，效果数值仍在执行时读取。

## 已有证据与接口边界

[饭团截图](research/riceball_photo_review_2026-09-08.md) 中本番前夜＋最终元气17、引擎隔离探针20的差异保留为后续校准案例。这涉及“使用后”与“最终移区”的跨阶段先后，本次字典序不会消除它；不把默认顺序标记为已获实机验证。

饭团首张实际用卡不计入自身元气参照，以及已观察到的分段元气／取整证据继续保留。原始截图、证据JSON与规则v3探针未覆盖。U02/U03/U07等精细排序实验降为暂缓，可在自然遇到时留证。

没有新增adapter字段。实况 `submitted/uncertain` 的原命令恢复、command_id、去重与确认后消费保持原协议。排序精度不足本身不触发“补读”或“引擎不支持”；缺少必要观察、缺少机制处理器仍按原接口分别报告。

内容包Schema及原生能力版本保持兼容；规则版本进入内容digest，因此旧规则的模拟快照明确拒绝用v4悄悄重演，需要旧存档时使用原规则版本。
