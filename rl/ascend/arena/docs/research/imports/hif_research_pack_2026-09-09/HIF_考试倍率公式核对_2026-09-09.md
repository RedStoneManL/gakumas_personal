# HIF 五场考试倍率：三维、属性判定、亲爱度与スター性

研究日期：2026-09-09。版本：v0.3，实测重建稿。所有数组统一为 **Vo / Da / Vi = 红 / 蓝 / 黄**，并非红 / 黄 / 蓝。

**目前可以给出一个能复算现有达标样本的公式；属性未达标已作为独立分支纳入，但惩罚幅度尚未用 HIF 完整实测校准。** 收集的 14 组记录覆盖选拔三场和本战两轮，其中 13 组三色全部重建成功，合计 41 / 42 个最终百分数相符。这是对已收集样本的解释能力，不是独立测试集准确率。

你特别补充的两点都影响模型：

- “一、二、三号属性”由该 P 偶像对应的考试配置决定，不能把当前三维数值从大到小排序后套公式。
- ◎ / ○ / △ / × 必须保存。△ / × 的影响可能同时传到另外两色，不能只降低该色倍率。开场第二段出现的约 ×1.5，有独立的亲爱度效果来源，不能解释为“三个 ◎ 相乘得到 ×1.5”。

基础表、场次和亲爱度效果来自公开主数据；倍率样本来自作者实际截图及你提供的完整汇总表。主数据快照为 `571dbb62601e78998cddeacdbce3ea1bc672d7fc`，提交于 2026-09-07。它是社区维护的数据镜像，不是客户端计算函数的官方说明。[考试基础表](https://github.com/vertesan/gakumasu-diff/blob/571dbb62601e78998cddeacdbce3ea1bc672d7fc/ProduceExamBattleScoreConfig.yaml)、[场次关联](https://github.com/vertesan/gakumasu-diff/blob/571dbb62601e78998cddeacdbce3ea1bc672d7fc/ProduceStepAuditionDifficulty.yaml)。

## 1. 现在可用的公式与证据等级

记：

- \(e\)：五场考试之一；\(r\)：该偶像的曲线族；\(c\)：Vo、Da 或 Vi。
- \(p_c\)：入场原始属性；\(S\)：**本场入场**スター性；\(T_e\)：本场スター性基准。
- \(L_{e,r,c}(p_c)\)：从主数据对应颜色的 Permil 列按相邻节点线性插值得到的数。
- \(H\)：亲爱度等对应的考试倍率因子；本次样本按 \(H=1.5\) 分析。
- \(Q\)：三维未达标的剩余系数；达标分支取 1，未达标分支仍是待验证模型。
- \(\lceil x\rceil\)：向上取整。

在**没有三维未达标惩罚**时，当前最能解释样本的计算顺序为：

\[
A_c=\left\lceil100+\frac{L_{e,r,c}(p_c)}{10}\right\rceil
\]
\[
B_c^{\rm internal}=A_cH,\qquad
B_c^{\rm display}=\lceil B_c^{\rm internal}\rceil
\]
\[
M_c^{\rm display}
=\left\lceil B_c^{\rm internal}\frac{K_e(S)}{1000}\right\rceil
\]

\(A,B,M\) 的单位全部是“百分数的数值”：例如 \(M=4397\) 表示 4397%，换成倍数为 43.97。

**固定的 +100% 不能漏掉。** 主数据的 Permil 列在这一重建中表示属性带来的增量；只算 \(L/1000\) 得到的不是完整基础倍数。上一版报告没有把这点算进完整预测，本版已修正。

**第二段显示值不应直接回填计算。** 例如 977 × 1.5 的内部值是 1465.5，显示为 1466；接着应使用 1465.5 去乘スター性，才能重建你的最终 Vo 倍率。

| 部分 | 本次证据 | 当前判断 |
|---|---|---|
| 六种曲线族、五场基准、150 个节点 | 主数据直接读取 | 配置事实，可信度高 |
| 节点间线性插值 | 公开资料站作者代码 + 样本重建 | 有支持；客户端数值实现未取得 |
| +100%、A 向上取整、B 保留内部小数 | 两组 A/B/最终值 + 外部样本 | 较强的经验重建 |
| 亲爱度 ×1.5 | 主数据效果链 + 样本 | 加成来源有直接数据支持 |
| 本战スター性斜率及千分位取整 | 一组 R1、两组 R2 未封顶完整样本 | 候选公式，仍需更多独立点 |
| 选拔三场未封顶スター性曲线 | 目前都接近 3 倍区间 | 尚未识别 |
| △ / × 惩罚、组合方式和所在层 | HIF 观察 + 全局配置 + 旧模式研究 | 已建独立候选分支，尚未校准 |

公开资料站的 [calcBattleScoreConfig](https://github.com/vertesan/hatsuboshi-library/blob/686ae0e07e2564ff0a7beec17db13acbeb0d779d/app/data/calculation.ts) 也按相邻节点求斜率；它用于展示的舍入不等于客户端内部算法。不能由“大部分样本对上”进一步声称所有属性、所有取整边界都已证明。

## 3. 重点补充：◎ / ○ / △ / × 怎样纳入

### 可以确认到哪一步

HIF 玩家攻略记录：有一项 △ 时，全体倍率会下降；HIF Wiki 也把该影响描述为跨颜色，并仍把详细公式列为调查中。这支持“各色不是完全独立函数”的处理方式。[Shato Monami 的实机攻略](https://note.com/syato_monami/n/n3e6218f3c356)、[HIF Wiki](https://seesaawiki.jp/gakumasu/d/H.I.F)。

| 图标 | 当前模型处理 | 尚不能声称的事 |
|---|---|---|
| ◎ 双圈 | 无短板惩罚分支 | 不能据此认定每个 ◎ 都提供一个独立乘数 |
| ○ 单圈 | 暂按无短板惩罚处理 | 仍需 ○→◎ 边界样本检查是否另有跳变 |
| △ 三角 | 激活该项短板，并影响三色 | 没有证据给所有 △ 固定扣相同百分比 |
| × 叉 | 同样激活短板；具体幅度随缺口建模 | 不能只按“× 的数量”算总倍率 |

**你说的开场“第二段 A→B”是否承载了全部图标修正，目前没有证明。** 已达标样本中的这一步吻合亲爱度 ×1.5；未达标惩罚可能已包含在 A 中，也可能在 A→B 生效。代码保留这两种位置供后续对照。

亲爱度来源可以沿主数据追踪：`CharacterDearnessLevel` 的对应等级引用考试加成技能，`ProduceSkill` 关联 `p_effect-audition_parameter_bonus_multiple-0500_0500`，`ProduceEffect` 的类型是 `ProduceEffectType_AuditionParameterBonusMultiple`，效果值为 500‰，即 +50%。同一系统中还有 50、100、150、200、300、400‰ 等等级效果。提高スター性**获取量**的 `star_permil_up` 是另一类效果。[亲爱度等级](https://github.com/vertesan/gakumasu-diff/blob/571dbb62601e78998cddeacdbce3ea1bc672d7fc/CharacterDearnessLevel.yaml)、[技能关联](https://github.com/vertesan/gakumasu-diff/blob/571dbb62601e78998cddeacdbce3ea1bc672d7fc/ProduceSkill.yaml)、[效果定义](https://github.com/vertesan/gakumasu-diff/blob/571dbb62601e78998cddeacdbce3ea1bc672d7fc/ProduceEffect.yaml)。

### 暂定惩罚函数：可试算，但不是已验证 HIF 公式

全局配置存在：

```text
produceExamBattleScorePenaltyMinPermil = 100
produceExamBattleScorePenaltyMaxPermil = 250
produceAuditionTrendAssessmentPermilSeparateEnable = true
```

HIF 的 `p_setting-7`、`p_setting-8` 另有 `produceAuditionTrendAssessmentPermilUpper = 110`、`Lower = 110`。字段存在是事实；**仅凭名称和数值，无法把 110 直接解释为“○ 是某基准的 110%”或“◎ 一律加 11%”。** [Setting](https://github.com/vertesan/gakumasu-diff/blob/571dbb62601e78998cddeacdbce3ea1bc672d7fc/Setting.yaml)、[ProduceSetting](https://github.com/vertesan/gakumasu-diff/blob/571dbb62601e78998cddeacdbce3ea1bc672d7fc/ProduceSetting.yaml)。

作为下一步回归的起点，采用下面这个**实验候选**。令 \(t_i\) 是惩罚所用阈值，\(J_i\) 是实际观察到的图标：

\[
q_i=
\begin{cases}
0,&J_i\in\{\text{◎},\text{○}\}\\
\dfrac{\lfloor250-150\min(p_i/t_i,1)\rfloor}{1000},
&J_i\in\{\text{△},\text{×}\}
\end{cases}
\]
\[
Q=1-\sum_{i\in\{Vo,Da,Vi\}}q_i
\]

主候选的插入位置为：

\[
A_c^{\rm penalty}
=\left\lceil100+\frac{L_{e,r,c}(p_c)}{10}Q\right\rceil ,
\qquad
M_c=\left\lceil A_c^{\rm penalty}H K_e/1000\right\rceil .
\]

这是“短板共同压低三色的属性增量，固定 100% 保留”的假说。斜率与相加结构借鉴公开的 Contest 惩罚写法，100/250 与当前全局设置相符；**它尚不是 HIF 实测拟合结果**。旧模式原作者的对照截图也显示，出现 △ 以下时，其他属性会参与某一颜色的倍率计算；但作者后来纠正过阈值判断，不能直接照搬其 2024 年门槛。[Contest 公式线索](https://wikiwiki.jp/gakumas/%E3%82%B7%E3%82%B9%E3%83%86%E3%83%A0%E9%96%A2%E9%80%A3)、[lull 原始检证](https://note.com/lal_ilul_elo/n/ndc72ead428c6)、[作者后续修正](https://note.com/lal_ilul_elo/n/na6c0a57bfc18)。

保留两个主要竞争解释：

1. \(Q\) 乘在已取整的整段 A 上，在 A→B 才生效，而非只乘属性增量。
2. 两项以上不足时，剩余系数为 \(\prod_i(1-q_i)\)，而非 \(1-\sum_iq_i\)。

**仅有一项不足的样本无法区分相加与相乘。** 要区分位置，最有用的是同一入场状态的 A、B 和最终菜单倍率；只拍最终倍率容易把短板惩罚与スター性因子混在一起。

下表只是说明模型行为的**假设试算**，不是新增实机记录：固定你 R2 的 Vo=2759、Da=1744、S=1083，将 Vi 改为 1000，并假设画面为 ◎ / ◎ / △，惩罚尺度临时用 1088。

| 假设 | 剩余系数 Q | 预测最终 Vo / Da / Vi |
|---|---:|---|
| 忽略短板，仅变更 Vi | 1 | 4208 / 2886 / 1882% |
| 候选一：扣属性增量 | 0.888 | 3786 / 2610 / 1723% |
| 候选二：A→B 扣整段 | 0.888 | 3737 / 2563 / 1672% |

这说明为什么低 Vi 可能让 Vo、Da 也下降，以及为什么惩罚所在层必须通过实际截图识别。**不能拿这里的 0.888 当作 Vi=1000 的 HIF 已知答案。**

### 图标门槛不能直接用主数据基准替代

现有 HIF Wiki 有少量带括号的观察值：例如本战均衡型第三属性 1087 为 △、1093 为 ○；突出型主属性 2018 仍为 △。它们缺少完整的卡片、场次和连续边界记录，不能直接写成“精确阈值=1093”或“所有角色=1100”。[HIF Wiki 的判定观察](https://seesaawiki.jp/gakumasu/d/H.I.F)。

因此 JSON 分别保存“主数据基准”和“观察到的图标”。代码默认不从三维自动推断图标；实验惩罚模式才允许把主数据基准暂作 \(t_i\)，并在输出中标注这一假设。后续有具体 P 卡的门槛实测时，可以直接覆盖。

## 5. スター性：本战有可计算候选，前三场斜率仍缺数据

在 \(S\ge T_e\) 的区间，候选形式为：

\[
K_e(S)=\min\left(3000,\;2000+
\left\lceil1000\frac{S-T_e}{D_e}\right\rceil\right).
\]

实际乘数是 \(K_e/1000\)。本战目前建议试算 \(D_{\rm R1}=270\)、\(D_{\rm R2}=325\)，而不是假定统一按 \(S/T\) 成比例。

| 场次 | 已知基准 | 当前数值证据 | 可使用的结论 |
|---|---:|---|---|
| 选拔 1 | 50 | S=150、165、195 时接近或达到 3 倍 | 未封顶斜率未知 |
| 选拔 2 | 200 | S=375、390 时接近 3 倍 | 未封顶斜率未知 |
| 选拔 3 | 400 | S=645、660 时达到 3 倍的重建成立 | 未封顶斜率未知 |
| 本战 R1 | 600 | S=854→2.941；885、907、915→3.000 | 候选 D=270 |
| 本战 R2 | 800 | S=1017→2.668；1083→2.871 | 候选 D=325 |

R1 的 854 来自 [Azhan 本战对照图](https://assets.st-note.com/img/1778985799-b4I3pQ7aOYuABFPeJvRczt28.png?width=1200)，R2 的 1017 来自同图，1083 来自你的记录。其他数据来源在样本表逐一关联。

在上述“线性、向上量化到千分位”的形式成立时，完整样本给出的分母约束为：

\[
269.925611\le D_{\rm R1}<270.212766
\]
\[
324.913892\le D_{\rm R2}<325.287356.
\]

所以 270、325 是自然且能复算的整数候选。这不是在所有可能函数中证明唯一解。R1 只有一个完整的未封顶星值，R2 只有两个，仍需要更多点检查弯曲、分段和角色依赖。

S 低于基准的部分同样未获得完整截图配对。代码中的 \(K=\lceil1850+150S/T\rceil\) 也只是实验插值，不能用它声称已经测出低星函数。Wiki 只提供约 1.85～2 倍、达标后约 2～3 倍的描述。[HIF スター性说明](https://seesaawiki.jp/gakumasu/d/H.I.F)。

## 6. 原始样本与复算结果

### 异常 SM-R2 为什么没有删掉

该图可读到 Vo / Da / Vi=1317 / 3200 / 1572，S=1110，倍率=2296 / 4813 / 2681%。按同一公式：

- Vo 和 Da 都要求スター性因子为 2.954；
- Vi 却要求 2.873；若同样用 2.954，应为 2757%，与原图相差 76 个百分点。

因此它无法由本版统一因子解释。其来源是开场加成画面，“动画未完全结算”是可能原因之一，但没有连续录像证明。也不能为让公式成立而把 1572 或 2681 改成另一数字。图中 R1 的 Vi 为 1587，R2 却为 1572，进一步说明不能默认该文章每张图来自严格连续的同一把。[异常原图](https://assets.st-note.com/img/1782366696-fgZ8YaExy1U0O7QMd6THmItu.png?width=1200)。

### 本次排除的几种简化

- 只取 Permil / 1000，不加固定 1 倍：无法还原你观察到的 A。
- 将 B 的显示值 1466 直接传入后续计算：你的 R1 Vo 会变成 4398%，而非 4397%；R2 会变成 4209%，而非 4208%。
- スター性简单用 \(2S/T\)：你 R2 应变成约 3968 / 2722 / 2007%，不符。
- 用 D=325 却完全不做千分位量化：AZ-R2 得到 3826 / 2553 / 2309%，后两色各低 1。这是引入星值量化候选的数值理由。
- 看见最终倍率不符就统一归因于“属性不达标”：SM-R2 只在 Vi 有明显矛盾，不能凭空用跨颜色标量惩罚把它抹平。

## 7. 下一批最有价值的实机信息

当前瓶颈是未达标和未封顶区间。继续收集全 ◎、星值封顶的高分截图，对这些未知量帮助较小。

| 优先级 | 要记录的变化 | 主要识别目标 |
|---|---|---|
| 最高 | 仅第三属性在 ○ 门槛上下，其他两维、场次、P 卡尽量相同 | △→○ 的跳变，是否连带改变两色 |
| 高 | 仍是 △，但离门槛远近不同 | 连续缺口效应，固定图标乘数是否错误 |
| 高 | 两项 △ 或 × | 惩罚相加、相乘或取最大值 |
| 高 | ○→◎ 门槛附近 | 是否有独立双圈奖励 |
| 高 | 选拔 1 的 S=50～150、选拔 2 的 200～375、选拔 3 的 400～645 内多点 | 前三场未封顶スター性函数 |
| 中 | 本战 R1 的 S 约 600～870、R2 约 800～1125 | 检查候选斜率及封顶边界 |

表中 870 / 1125 是本版连续斜率候选暗示的端点，不是已经拍到的精确封顶门槛。整数星值和千分位量化还会影响边界。

每组最好保留：场次、P 卡或卡片 ID、玩法类型、亲爱度等级、原始 Vo / Da / Vi、**入场**スター性及基准、三个图标、A、B、动画结束后的局内菜单最终倍率。录一段连续开场视频比三张无法确定时序的截图更容易排除混淆。JSON 已附可复制的空白记录模板。

若能取得未达标时的 A，不必先知道スター性公式，就能检验主候选的共同剩余系数：

\[
\frac{A_c-101}{L_c/10}<Q\le\frac{A_c-100}{L_c/10}.
\]

把三色区间求交；如果交集为空，就排除“同一个 Q 乘属性增量后再加 100”的解释。附带代码的 `infer_penalty_from_A` 已实现这一辅助计算。

如果三维和图标不变、仅スター性改变，短板影响可以在倍率比值中近似抵消；这类记录适合先识别星值曲线。若只有最终画面，而且亲爱度、图标、入场星值都不清楚，则无法唯一拆出这些因子。

## 8. 可复算文件与使用方式

- `hif_multiplier_research_2026-09-09.json`：30 组曲线、150 个节点、五场基准、六族映射、14 组原始记录、每条原图 URL、证据标记和下一批记录模板。
- `hif_multiplier_model.py`：只用 Python 标准库，采用分数运算避免浮点误差污染取整；保留未取整与显示值。

将这两个文件放在同一目录。复算你的 R2：

```bash
python3 hif_multiplier_model.py \
  --family voda-03 --stage round2 \
  --stats 2759 1744 1209 --star 1083 \
  --judging-icons ◎ ◎ ◎
```

结果为 `score_percents: [4208, 2886, 2128]`。

审计全部原始记录：

```bash
python3 hif_multiplier_model.py --audit
```

输出 14 组、13 组全相符、41 / 42 个最终百分数相符，并显示异常行，绝不静默删除。

实验性未达标试算：

```bash
python3 hif_multiplier_model.py \
  --family voda-03 --stage round2 \
  --stats 2759 1744 1000 --star 1083 \
  --judging-icons ◎ ◎ △ \
  --penalty-mode settings-prior --allow-experimental
```

如果要检查“第二段 A→B 扣整段”的解释，再加 `--penalty-placement after-A`。两项不足时可比较 `--penalty-combination additive` 与 `multiplicative`。已实测的惩罚阈值可用 `--penalty-thresholds VO_T DA_T VI_T` 覆盖；这里不是只输入一个通用的 1100。

程序对 △ / × 不会静默按全达标计算，也不会自动把四种图标转换成已证实的固定奖励表。**这里重建的是界面百分数，不是每张卡的实际得分取整。** 战斗评分器最终应该使用显示倍数还是内部未取整值，仍需一张已知基础输出的卡牌得分事件验证。
