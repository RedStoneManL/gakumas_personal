## 实现边界

- 证据等级 O/M/V/H/U 分别代表官方帮助、主数据或协议、游玩或社区、假设、未知；详见报告。
- HIF 慰问品的粉丝投票追加 P 点概率为 **0**，来自官方排除说明。道具和支援产生的额外 P 点另行触发。
- `unknown_probabilities` 中的 `null` 表示尚未识别，不能转成 0、0.5 或均匀分布。
- 六组 `penlight_weight_tables` 仅用于应援棒战斗内补基本卡；不能用于咨询、外出、上课或慰问品。
- `events` 和 `suggestions` 保留主数据原字段。先支付选项头部成本，再解读效果；`alwaysSuccessful=true` 优先于默认成功率字段。
- `Permil` 的分母为 1000，`Permyriad` 为 10000。原始字段中的默认 0 不一律意味着不触发。
- `card_metadata` 是 1714 条卡片版本记录，不是奖励池；联合键为 `(id, upgradeCount)`。`card_customizations` 的联合键为 `(id, customizeCount)`；技能使用 `(id, level)`。
- `support_events` 等全局参考目录必须按编成、等级、计划和当前合法性筛选。目录成员不等于 HIF 中某入口的候选成员。
- `card_growth_effects` 和道具战斗效果用于追踪数值；本包没有完整战斗执行器，仍有需从固定版本源文件解析的引用。
- 道具触发次数、徽章已用次数、面板开关和选拔开始时的亲爱度快照必须进入状态。本战继承不能全部重置。
- 延续此前考试倍率模块时，继续保存 Vo/Da/Vi、スター性、审查类型、流 1/2/3 映射与 ◎/○/△/×；本报告不假定它们改变日常奖励稀有度。

## 后续采样

记录完整候选集合和未选中的卡，区分“环境展示概率”与“策略领取概率”。对商店逐货位记录刷新前后、价签、已购与服务状态；同一批货位保留共同 `offer_set_id`。支援事件还应记录未发生的日数。
