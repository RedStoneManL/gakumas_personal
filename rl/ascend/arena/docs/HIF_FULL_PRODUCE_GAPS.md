# HIF 两剧本：精度与模型差异清单

规则版本：`hif-report3/2`。本文把已经运行的近似模型与实机精度差异列出；具体接口见 [完整交付](HIF_REPORT3_RL_READY.md)。选拔 → 本战 R1 → 中场 → R2 属于同一套能力范围。没有要求追加实机录像作为训练前置。

## 证据优先级与冲突处理

1. gktools 负责局内既有元件，用户指定它为 golden；原 vendor 文件保留。
2. 固定 master snapshot 负责身份、触发器、事件成本、效果、进化边与考试配置。
3. 官方帮助负责可达性、时序、失败/放弃/回忆资格等语义；本地保存网页。
4. 用户接受的 HIF 研究公式、Report 3 与后续考试研究给出数值模型。未确认概率配置化，附默认值和来源，不以无效果替代。

| 冲突/旧实现 | 本版处理 |
|---|---|
| R1 也套 R2 的星性奖励曲线 | 五场独立曲线；raw 奖励与 R1×1.2 登记分分开 |
| 星性审查基准当作奖励上限 | 选拔奖励上限 40/110/110，本战 120/150；基准 50/200/400/600/800 只用于对应换算 |
| 评价再估算一遍 R2 星性 | 用实际接受结果后的 star，保留两轮 raw，避免双计或逆推取整 |
| 考试节点自动触发咨询／特别指导 | HIF 默认移除，只有实际选了对应行动才触发 |
| 重试沿用上次剩余饮料/一次性状态 | 恢复本场考前状态；R2 锚点位于中场之后 |
| 选拔落败也发突破星性、可导出正式回忆 | 不发突破奖励；仅保留诊断记录，不发选拔交接 |
| 取得过、之后删掉的卡仍进入回忆抽样 | 只用结束时永久持有的卡组 |
| 非字典编成未冻结，交接后可能回到默认偶像 | 所有输入统一冻结实际编成；旧交接包按偶像 ID 恢复，身份冲突拒绝 |
| 初始卡引用共享 master，其他环境可能继承被改写的 ID/效果 | 每个物理副本独立深拷贝；身份持久分配，不随位置变化或删除后复用 |
| 技能卡 support 概率当作获得卡的永久强化率 | 独立考试内临时强化机制；普通奖励强化率只来自来源池配置 |
| 随机换卡绕过来源池、复制卡复用 instance ID | 换卡接来源 kernel；复制深拷贝并分配新 ID |
| Switch 被理解为局内按钮 | 复用账户开局转换配置、PLv 门槛与有效卡池；不增加局内转换按钮 |
| 内部 StepSkip 与正常休息混同 | 25% opt-in 规划动作；默认 HIF 菜单不开放，普通休息仍按原值 |

## 已执行但仍为近似的部分

| 项目 | 当前模型 | 影响范围／替换位置 |
|---|---|---|
| 事件出现概率 | 全局基础概率、卡/事件修正、事件权重与合法日可配 | `support_event_*`；影响事件收益期望 |
| 技能卡 support 抽样 | 每张支援使用主数据基础率 ×（1＋该卡解锁技能相对增量）；按来源独立抽样、合法手牌均匀选目标 | 相对增量解释、编成顺序、目标选择、回合开始预约后生效为声明的模型；844 个临时高阶效果用 master 差值转换原生 AST，见 [支援说明](HIF_SKILL_CARD_SUPPORT.md) |
| 各来源奖励池 | 每个池独立合法成员/权重/升级率；未知时明确均匀默认 | `research_config.pools`；影响拿卡/饮料/中场概率 |
| SP 和副属性 | 基础 0.10，边缘概率独立，副属性默认较低者 | `sp_base_rate/sub_stat_policy`；影响育成成长 |
| 进化与商店 | 四选三均匀；未知槽数、尾端价格、SSR 强化概率可配 | 特殊道具、普通咨询、中场说明中的配置 |
| 默认回合随机与 NPC | 固定配额/末三回合，首回合概率与中间 shuffle；NPC 区间中点或整数均匀 | `courses`；master 端点与人物身份不变 |
| HIF 属性不足分支 | master 属性基准作门槛，settings-prior 惩罚 | `courses.scoring`；完整 ○/△/× 实机边界未知 |
| 亲爱度得分因子 | 默认研究包的 1.5，可显式覆盖 | `courses.dearness_factor`；不与星性获得率混用 |
| 选拔低分三维奖励 | 线性到已知上限，按真实颜色得分分池，最大余数分配 | `exam_rewards.stat_cap_scores`；高分总上限固定 |
| R1 P 点曲线 | raw 400000 达到 200，低分线性 | `exam_rewards.round1_point_cap_score` |
| 回忆服务器抽选 | 最终卡实例、概率/槽位/强化与定制保留、能力权重可配 | `memory_generation`；再生成仍需模拟票并择一 |
| 重试随机种子 | 恢复条件、保留已扣次数、继续环境 RNG | 精确服务器种子协议未知；本地可恢复复现 |
| 同分名次和取整 | 玩家同分优先；声明的整数边界和分池规则 | 完整客户端同分与细碎取整仍有精度差异 |

这些差异会影响最优策略和绝对分数，但都有实际执行路径，可用于当前版本训练。实验必须保存规则版本、主数据/源码 hash 和完整研究配置；不要混合不同环境模型的标签。

## 能力范围

- 固定快照覆盖 10 个偶像的完整五场考试配置、6 个曲线族。未关联的其他偶像可显式使用已知 profile 作为规划替身或自定义课程；默认不会猜一个身份。
- 原始场景 gimmick 全部为第 99 回合元气 +1 的占位数据，正常 9/10/12 回合不可达；当前不把这些占位行编成虚构的常规应援。人为超过 98 回合属于扩展课程差异。
- 同步内部选择由 `produce_choice_selector` 执行，外部记录训练样本。checkpoint 保存公共决策边界，不序列化 Python 回调栈。
- 模拟局内与本次培育的资源、触发和产物；账户 AP、跨局钱包、成就/回忆仓库由调用方维护。再生成与重试有本地费用/次数配置，不操作真实账户。
- `snapshot`、私有 RNG、课程抽样历史用于诊断与恢复，不可输入策略；未提供公平信息集 MCTS 的条件重采样算法。

当前新增机制的最终验收数量见 [完整交付的验证记录](HIF_REPORT3_RL_READY.md#验证产物)。出现未知实际执行效果时仍严格报错，不将异常改成合法 0 分训练样本。
