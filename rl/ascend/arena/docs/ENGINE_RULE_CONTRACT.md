## 数值与卡牌效果

- `ExamLessonBuffMultiple`：集中强化，改变集中对分数的贡献，包括集中倍数参照部分，不改变获得的集中层数。
- `ExamReviewMultiple`：好印象强化，只改变自然好印象结算，不改变获得的好印象量，也不强化普通好印象参照技能。
- `*Additive`、`*AdditiveFix`：继续分别表示获取量百分比增加与固定值追加。
- 效果按卡文顺序执行，每段资源变化独立触发。追加发动重复整个序列，使用计数只增加一次。
- 固定元气绕过やる気与元气无效等普通修正。普通／穿透费用、正文扣体力、强化状态费用保持独立路径。
- 低下状态恢复按请求的**种类数**清除整种状态，较新授予的优先；防低下状态仍用于阻止授予，两者不互换。
- 跳过回合的回复受体力回复无效约束。
- 好印象／好调完全耗尽后再次获得，重新开始新状态的免衰减寿命；未耗尽时续加保留原寿命。

## 批次与执行阶段

同一事件先决定所有监听者的发动资格，再执行选中效果。资格不随前一个效果对资源的修改被补获或取消，**效果数值在执行时读取**。新注册的监听者不加入已收集的批次。有限触发次数与每回合限制在嵌套事件前预留，避免重复消费。

按用户2026-09-08最新取舍，**同阶段的P道具／状态附魔监听者采用统一默认排序** `stable_id_lexicographic/1`：先按 `enchant_id`，相同则按 `source_identity`（缺省为空字符串），再按数值 `uid`。字符串使用区分大小写的Unicode字典序，不按中文／日文显示名、数值效果大小、UI位置或道具／状态类别排序。`trigger_batch.detail.trigger_order_policy` 记录此政策；`decisions` 给出本批实例顺序。相同定义的多个实体仍保留各自次数，原有同一道具去重规则继续有效。

此默认只排列同阶段的附魔监听者，不重排卡文效果、阶段表或自动用卡FIFO队列。卡片自身成长监听者仍在附魔批次之后按既有区域／牌序处理。精确游戏次序作为后续校准项，不要求穷举，不阻塞HIF基础建设。替换点是 `resolution.trigger_order_key`；后续改变语义时同步升级规则版本，详见 [本次交付](ARENA_TRIGGER_ORDER_UPDATE.md)。

**已知近似，暂缓校准**：下表所写“使用后→最终移区”仍是当前实现，已由 [用户饭团日志](research/riceball_photo_review_2026-09-08.md) 暴露偏差。本番前夜＋的除外紫灯先以やる気6获得元气7，之后佑芽使用后道具才使やる気6→9；当前引擎反过来得到元气10。此例涉及不同阶段，改同批字典序不会消除差异。原图、17对20的最终元气及隔离探针保留，不把默认顺序标为游戏已验证规则。

主数据的 `StartPlay` 原文为「ターン開始後」、`StartExamPlay` 为「レッスン開始後」。它们已经移出每次出牌路径。

| 边界 | 当前执行顺序 |
|---|---|
| 开场 | 开场附魔；进入第一回合 |
| 回合切换 | 衰减旧状态；解除旧全力；按上回合末资格进入全力 |
| 应援／麻烦 | 固定本批资格；处理全力解除后触发；执行已选中的应援／麻烦 |
| 开始阶段 | 开始时；正常抽牌；全力回收保留牌；开始后 |
| 抽牌之后 | 首回合开始后／记忆；到期预约；每N回合 |
| 出牌前 | 卡内条件；费用支付；实际费用体力损失事件一次；使用时；第N次使用事件 |
| 卡身 | 有序正文、嵌套资源／移区事件；重复整个正文 |
| 出牌后 | 记录实际使用；状态费用事件；使用后；每N次使用后；移区；执行待使用队列 |
| 结束 | 若跳过则跳过事件；结束触发；自然好印象；状态收尾；保存下回合全力资格 |

每N回合的资格精确时点、状态费用与使用后的相互顺序仍属于暂定政策，详见后文。首次全力资格没有上回合末时按开场状态初始化。额外回合继承原最后回合属性。

数据创作新增阶段别名：`exam_start_after`、`turn_start_after`、`stamina_cost`、`stamina_loss`、`buff_cost`。既有阶段别名继续有效。例如：

```json
{
  "id": "demo/after_start",
  "phase": "turn_start_after",
  "field": "ProduceExamFieldStatusType_LessonBuffUp",
  "value": 3
}
```

此对象放入已有内容包的`triggers`；通过`passives`引用并指定效果。完整卡牌／事件／剧本创作方式仍见 [CONTENT_AUTHORING.md](CONTENT_AUTHORING.md)。

[完整最小包](examples/rule_alignment_minimal.json) 展示同批冻结资格、执行时读取数值：第一回合集中3但分数0；下一回合集中6、分数14。预期已通过公共 `create_exam`／`act` 入口核验。

## 准备使用、实例寿命与计数

普通移动／资源触发可以插入当前处理。自动用卡进入准备队列，在外层效果组结束后执行。卡身、其前后使用事件及移区属于一次完整出牌组；饮料的有序效果属于一组；同阶段触发批次属于一组。自动卡产生的新准备卡继续按当前FIFO政策执行。

自动使用按来源决定费用，不占用玩家行动窗口，但计入实际使用次数。目标卡的使用条件不满足时，仍计使用，正文不生效。付费自动卡执行前再次检查可支付性；不足则按暂定政策取消，不发生部分扣费。

再演首次注册事实按`(card_uid, enchant_id)`保留至本场结束，附魔次数耗尽不会删除这项事实。副本获得新UID，有独立注册记录。同UID移区或预览快照不会变成新副本。

行动追加以剩余单位和授予时点记录。手动卡正文完成后优先消费最早的一个追加单位；自动卡不消费玩家窗口。可操作阶段新授予且未消费的单位可跨到下回合；回合开始授予与已跨过一回合的单位在本回合末过期。多个新旧来源并存时的具体合并政策仍需采样。

外部计数语义继续采用`arena-exam-counters/1`：

- `turn`：考试回合；内部选择不增加回合。
- `plays_used`：已完成的实际用卡次数，包括自动使用，不包括正文追加发动。
- `plays_remaining`：玩家剩余行动窗口，自动使用不消耗它。
- 第N次使用前事件按本次即将完成的序号判定。卡身中的旧累计使用数参照保留“此前完成次数”政策；当前卡是否应计入某类数值参照单独列入实机采样。
- 上一张卡的主动／心态类别另存卡UID，不再用本回合得分次数或总出牌次数代替；跨回合保留。

## 预约来源与恢复

预约记录效果ID、到期回合、次数、来源及来源卡UID。普通卡／饮料预约仍能产生适用的直接资源变化事件，附魔建立的预约保留持续来源。到期执行使用`scheduled:`来源链，既保留直接来源分类，又避免错误继承卡身成长。嵌套预约继承政策暂定为延续该来源链。

模拟器新增的准备队列、首次注册集合、全力资格、上次用卡身份、负面状态顺序与来源上下文被纳入预览快照。ContentExam公开恢复继续使用完整内容digest、种子、原动作及选择日志重放；自动卡内部再次发生选择时也从同一动作的原始检查点恢复。

`arena-content-exam-session/1`封装保持兼容，但旧规则digest的模拟快照**明确拒绝**由新规则重演。需要旧存档重放时使用原规则版本，不悄悄迁移最终状态。

实况`arena-session/1`的`submitted/uncertain`恢复与去重账本没有改动，恢复返回原始命令及`command_id`。本次增加的模拟器状态不等于已扩展实况输入Schema；当前尚无完整实况绑定的预约、再演、历史字段仍按已有接口报告`unsupported`，不能虚构缺失事实。

## 有待实机确认的政策

当前实机工作按用户最新范围只针对HIF。下面保留完整机制边界，但U05的パニック/偶像之路专属行为，以及Q11的人为跨计划组合不作为本阶段采样或完成要求。细粒度触发排序（包括U02/U03/U07）先用确定性默认，不安排专门穷举；可操作优先级见 [HIF真实卡牌清单](RULE_ALIGNMENT_REAL_CARD_RECIPES.md)。

| 编号 | 当前可追踪的政策 | 尚不能宣称的内容 |
|---|---|---|
| U01 | 集中强化保留小数至既有分数边界；额外参照部分沿用原分段取整 | 混合倍数、强化与多段舍入完全一致 |
| U02 | 每N回合在预约之后收集资格并执行 | 资格是否应更早冻结 |
| U03 | 状态费用事件在正文后、使用后事件前 | 二者是否实际同批及精确次序 |

| U06 | 嵌套预约延续来源链；附魔边界转为持续来源 | 所有特殊卡的预约分类 |
| U07 | 同时准备的卡按确定性FIFO执行，过长连锁显式报错 | 游戏全部并列排序规则 |
