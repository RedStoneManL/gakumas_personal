# 第一版训练工程验收

日期：2026-09-10。结论：独立训练工程已经实现并通过下面范围的验收，可以进行有边界的训练实验；尚未证明策略收敛、自然通关五场或全部引擎机制语义等价。

## 实现与审查

三个子代理分别实现 Arena/任务适配、编码/网络、PPO/运行入口；主代理统一合同、审查并运行集成验收。训练代码位于 `gakumas_training/`，Arena 仍为独立依赖。Arena 修改仅增加公开状态与执行帧，涉及 `produce/public_state.py`、`simulation/produce/runtime.py` 和 `customize_items.py`。

审查中已修复候选没有正确连接到卡牌、深层 AST 数值无法到达动作、类型命名空间冲突、整数键、展示字段误判、支援历史等级过度展开、合桶依赖缓存历史顺序、JSON loadout 数组不符合 Arena 类型要求，以及安装包默认配置/命令退出码等问题。

CPU 更新/恢复探针使用宽度 32、符号维度 8 的小模型，每任务 543,234 参数，单 worker、每批一局、一个 PPO epoch。它验证参数更新与可复现性，不能用一局的奖励或优势标准化结果判断学习质量。CLI 则使用默认宽度 64、每批两局、两个 epoch，并执行独立评估。

探针中的单场采集/更新分别约 1.25/0.52 秒，全培育约 10.52/1.56 秒。包含不同初始化成本、网络规模、流程长度及测试并发，不能与旧实验直接比较吞吐，也不能推断 GPU 或更大批量的长期性能。

## 尚未证明与明确限制

1. **没有自然通关 3＋2 的结果。** 未训练策略、六支援启发式和独立旧考试 actor 诊断都在选拔失败；没有改对手、回合或分数来制造通过。软件交接测试不能代替这项验证。
2. **选拔失败评价采用显式映射。** `final_formula_zero_unplayed_v1` 将实际终局资源代入 Arena 最终公式，未进行本战计零分；它尚未与游戏的真实失败评价核对。引擎异常或人工截断不会走这条映射。
3. **并行采样与恢复边界。** 当前 worker 数量可填任意正整数，独立Arena/Node、主进程统一模型与词表；测试覆盖有序采样、事务丢弃、CPU恢复、异常清理、热改局数后的连续种子和检查点恢复。提供同模型/引擎/任务的四项性能参数迁移；没有中途对局快照续跑或跨设备逐位一致性保证。后续移除了原有的 128 上限，验证范围见 `rl/ascend/ACCEPTANCE.md`；较高worker数量是配置能力，不代表已在每一种硬件上测得加速。
4. **聚合是保守的。** 已实现通用贡献账本和部分实际支援规则的自动投影；复杂独立概率、次数或时序仍保留实例。未证明所有机制和未来剧本都能自动合桶。
5. **容量是实测样本范围。** 9,868 节点来自一条六支援失败路线，不是全部自然完整培育的峰值。新机制仍需准入、可达路径和容量验证。
6. **没有开始正式长训，也没有声称策略提高。** 默认编成用于运行起点；六支援诊断的 PLv80/成长面板配置只用于额外覆盖，不能代替正式实验的编成与采样分布。旧 Colab 准备 ZIP 尚未包含本训练包。
